# 投资 SDD 设计方案（讨论稿 v0.1）

> 面向「投资决策与复盘」场景的规范驱动开发（SDD）体系方案。
> 以 novel-sdd / zy-sdd-spec / benben-spec 三个技能为参考，借鉴其「状态机 + 三重约束 + 护栏脚本」骨架，翻译成投资语言。
> 适用范围：个人投资者 · A 股 + ETF · 决策记录与复盘闭环（暂不涉及组合级资产配置系统）。
> 状态：讨论稿，未落地技能。**不含任何真实投资/交易数据。**

---

## 一、为什么投资也需要 SDD？（背景与目标）

### 1.1 投资的本质问题：决策不可追溯

个人投资者最大的问题不是"不懂"，而是**决策过程不可追溯**：

- 买入时"觉得会涨"，跌了割肉时"觉得会继续跌"——事后说不清当初的逻辑是什么
- 复盘时天然有"幸存者偏差 + 结果归因偏差"：赚了归功于自己，亏了归罪于市场
- 同样的错误反复犯：追高、不止损、仓位失控，因为每次都是一次性决策，从不沉淀

这和小说的"写着写着放飞自我、支线失控"高度同构。SDD 的核心能力——**在明确的边界内生成，让过程可复核、可追踪、可验收**——恰恰是投资纪律缺失的解药。

### 1.2 目标

1. **决策先于交易**：任何一笔交易背后都有一份"决策书"（spec），先写清楚为什么买/买多少/何时卖
2. **复盘闭环**：每一笔完结的投资必须有一次"复盘评审"（review），对照原决策验收
3. **纪律可执行**：把个人投资纪律沉淀为规则基准（RULES.md），并让脚本/流程兜底执行
4. **经验可复利**：策略、标的研判等知识资产独立沉淀，跨决策复用（类似 novel-sdd 的世界观包）

## 二、三个参考技能点评：分别好在哪里，局限在哪

> 三技能一脉相承：benben-spec（招行 PaaS 重装版）→ zy-sdd-spec（通用精简版）→ novel-sdd（小说领域包）。
> 它们共享同一内核：**SPEC 状态机（draft→review→accepted）+ 三重约束（deliverables/out-of-scope/validation）+ 任务卡验收 + 护栏脚本兜底**。

### 2.1 novel-sdd —— 本次设计最重要的参考（领域化范式的标杆）

**评价：构思最巧。** 它证明了 SDD 不只是"软件开发方法论"，而是"**让 AI 在边界内干活**的通用范式"——把小说写作这种模糊、长流程、容易失控的创造性工作，用 SDD 框架管理住了。

亮点：
1. **领域化映射干净利落**：spec→作品设定书、task→章节卡、RULES→写作规则、review→编辑评审。每个概念都翻译成了小说作者能直接理解的载体，而不是套着软件术语的壳
2. **领域专属校验**：`guard_novel.py` 里新增的校验非常精准——伏笔"埋→回收"对照（不回收=缺陷，对应投资里"假设未验证=缺陷"）、人物卡弧光、起承转合四段、章节卡每章至少一钩
3. **"可复利资产"概念（worldviews 世界观包）**：世界观独立于具体故事走自己的状态机，可被多部作品引用。这是所有参考技能里最超前的设计——知识的沉淀与复用

局限：
1. **骨架仍照抄 zy-sdd-spec**：状态机、任务卡结构几乎原样复制，通用层的"模糊词检测"等校验对小说场景帮助有限
2. **无样例库支撑**：测试作品还停留在模板复制阶段，没有展示"一部已经跑完的作品"长什么样
3. **护栏脚本对"文笔/质量"无能为力**：只能校验结构和纪律（伏笔有没回收），校验不了"这章写得精彩与否"——投资同理，脚本校验不了"这个判断对不对"，只能保证"有记录、有对照"

### 2.2 zy-sdd-spec —— 最适合当"母版"的通用骨架

**评价：最稳健的基座。** 从 benben-spec 提炼出来的纯骨架，零技术栈绑定，机制极简但闭环完整。

亮点：
1. **去技术栈、去重型机制**：只留 SPEC（三重约束）+ PLAN/TASK（验收清单）+ 状态机护栏，任何领域都能套
2. **护栏脚本质量高**：`guard_spec.py` 的校验规则克制且有效——状态机强制 review 才能 accepted、DONE 前验收清单全勾、BLOCKED 必须登记原因、模糊词检测（"待定/可能/后续"这类范围未定的词直接拦下）
3. **场景化任务模板**（logic/db/web）：按任务性质选模板，很好的"轻量差异化"思路，投资场景可借鉴为 trade/monitor 等卡型

局限：
1. **纯骨架 = 无领域语义**：它只保证"流程规范"，不保证"领域正确"。投资场景如果直接用 zy，写出来的是"需求规格"而不是"决策书"
2. 不含"可复利资产"层（世界观包在 zy 里没有对应物）
3. RULES.md 的机制章节（12-15 章）是留给重型团队的可选扩展，个人场景用不上

### 2.3 benben-spec —— 机制最全，但对个人场景过重

**评价：重型武器，招行 PaaS 实战出身的"全家桶"。** 对理解"SDD 能长多大"很有价值，但不建议个人场景直接套。

亮点（值得借鉴到投资场景的个别机制）：
1. **ADR（架构决策记录）机制**：标准结构是 背景→选项→结果→理由，一页 A4。**投资决策书本质就是一份"投资 ADR"**——这个洞察是本方案的重要基石
2. **"真源唯一 + 分层档案"思想**：项目级（过程态）→ 应用级（档案态）单向流动。映射到投资：单笔决策（过程态）→ 标的库/策略库（档案态）
3. **接口条目状态机（proposed→active→deprecated→removed）**：可以借鉴为"持仓标的"的生命周期管理
4. **review 拦截机制**：多应用变更必须有证据否则 review 拦截——对应投资里"决策必须有依据，不能凭感觉"

局限（为什么不能直接用）：
1. **深度绑定招行技术栈**：Step/Service/Support/Mapper/server.xml/LPDBUtils，换个人场景全是噪音
2. **机制太重**：应用级台账、真源翻转模型、HTML 看板、跨技能联动……单个人炒 A 股完全用不上
3. 模板里塞满了团队专属验收项（事务边界、XML 配置），个人投资场景不存在这些概念

### 2.4 三技能对比总结表

| 维度 | benben-spec | zy-sdd-spec | novel-sdd | invest-sdd（本方案） |
|---|---|---|---|---|
| 定位 | 招行 PaaS 重装版 | 通用精简骨架 | 小说领域包 | 投资领域包（目标） |
| SPEC 载体 | 需求规格 | 需求规格 | 作品设定书 | **标的决策书** |
| 重型机制 | 应用台账/看板/ADR | 全部去掉 | 世界观包 | **策略包/标的库**（借鉴世界观） |
| 领域校验 | 技术栈硬规则 | 无（纯流程） | 伏笔回收/人设 | **假设验证/持仓漂移/止损纪律** |
| 技术栈绑定 | 深 | 无 | 无 | 无 |
| 对投资方案的启发 | ADR 机制、档案分层 | 骨架+护栏脚本 | **领域化范式 + 可复利资产** | —— |

**一句话结论：以 zy-sdd-spec 为骨架（状态机+护栏脚本），学 novel-sdd 的领域化翻译（把三重约束翻成投资语义）+ 可复利资产（策略包），借 benben-spec 的 ADR 思维（决策书即 ADR），做一个 invest-sdd 领域包。**

## 三、投资场景痛点分析与 SDD 解法对照

### 3.1 六大痛点 → SDD 机制

| # | 痛点 | 症状 | SDD 解法 |
|---|---|---|---|
| 1 | **决策无记录** | 买卖凭感觉，事后说不清逻辑 | spec→**决策书**：买入前必须写投资假设 |
| 2 | **复盘拍脑袋** | 赚了归功自己，亏了怪市场 | review→**复盘评审**：强制对照原假设验收 |
| 3 | **情绪化交易** | 追涨杀跌、手痒频繁操作 | **out-of-scope + review 关卡**：accepted 前至少过一遍自我评审 |
| 4 | **持仓漂移** | 说好长线变短线、仓位失控 | **状态机 + 持仓卡**：持有阶段定期校验逻辑，仓位超限报警 |
| 5 | **经验不沉淀** | 同样错误反复犯 | RULES.md（纪律）+ 策略包（可复利资产） |
| 6 | **假设不验证** | 买入逻辑从不对账 | **复盘闭环**：closed 前必须做假设兑现对照（对应 novel 的伏笔回收） |

### 3.2 SDD 核心概念 → 投资语义完整映射表

| SDD 概念（zy/novel） | 小说映射（novel） | 投资映射（invest-sdd） |
|---|---|---|
| spec.md（需求真源） | 作品设定书 | **标的决策书**（decision.md）：投资假设+买卖计划 |
| deliverables | 字数/章节/伏笔清单 | 交易交付物：建仓/加减仓/清仓执行 + 预期收益 + 决策材料 |
| out-of-scope | 不写 XX（防加支线） | **不做什么**：不追涨停、不加杠杆、不做 T（防冲动交易） |
| validation | 主题/人设/伏笔回收验收 | 复盘验收：假设兑现？止损/止盈触发？纪律遵守？ |
| RULES.md（规则基准） | 写作规则 | **投资纪律**：仓位上限、止损线、持仓集中度、禁止项 |
| plan.md（执行计划） | 章节清单 | **交易计划**：分批建仓表、仓位分配、止盈止损点 |
| task 卡 | 章节卡 | **交易执行卡**（一笔一卡：买入/卖出/加仓） |
| review.md（评审） | 编辑评审 | **决策评审/复盘表** |
| spec 状态机 draft→review→accepted | 草稿→评审→定稿 | **idea→research→review→accepted→executing→holding→closed** |
| task 状态机 READY→…→DONE | 章节写作状态 | 交易执行状态 READY→IN_PROGRESS→DONE |
| 世界观包（可复利资产） | 世界观/设定集 | **策略包**（红利/网格/定投…）+ **标的研报库**（公司卡片） |
| ADR（benben） | （无直接对应） | **决策书即"投资 ADR"**：背景/选项/结果/理由一页纸 |
| 应用级台账 apps/（benben） | （无） | 持仓总账 + 策略库索引（档案态） |

**最关键的三个翻译：**
1. **spec（需求真源）→ 标的决策书**：一标的一决策（或一操作一决策）。决策书就是"投资 ADR"——说明为什么买（背景）、有哪些选择（选项）、最终买什么（结果）、关键依据（理由）
2. **review（评审）→ 复盘**：accepted 前的 review 是"事前自我挑战"（这个逻辑经得起质疑吗），closed 前的 review 是"事后复盘"（假设兑现了吗）——一个防冲动，一个防遗忘
3. **伏笔回收（novel 领域校验）→ 假设对照（invest 领域校验）**：小说里埋了不回收 = 缺陷；投资里写了假设不对账 = 缺陷。这是守护"复盘闭环"的护栏

## 四、invest-sdd 结构设计

### 4.1 目录结构（仿 novel-sdd 布局）

```
invest-sdd/
├── README.md                  # 体系入口（用户看）
├── RULES.md                   # ★投资纪律基准（用户可编辑，validation 依据）
├── bin/
│   ├── init_invest.py         # 初始化（幂等不覆盖）
│   └── guard_invest.py        # ★护栏脚本（状态机/假设对照/持仓漂移校验）
├── decisions/                 # 决策层（唯一真源）：specs 的领域化
│   ├── _templates/
│   │   ├── decision.md        # 决策书模板（spec.md 领域化）
│   │   └── review.md          # 决策评审 + 复盘模板
│   └── <标的id>/              # 如 600xxx、000xxx、510xxx-红利ETF
│       ├── decision.md        # 决策书（状态机：idea→…→closed）
│       ├── review.md          # 评审/复盘记录（accepted、closed 前必填）
│       └── trades/            # 交易记录（执行层，见下）
├── plans/                     # 执行层
│   └── _templates/
│       ├── plan.md            # 交易计划（分批建仓表/退出条件）
│       ├── task.trade.md      # 交易执行卡（一笔一卡）
│       └── task.monitor.md    # 持仓跟踪卡（定期检查）
├── strategies/                # ★策略包（可复利资产，借鉴 worldviews）
│   ├── _templates/
│   │   ├── strategy.md        # 策略包：适用条件/纪律/不适用场景
│   │   └── strategy_review.md # 策略评审
│   └── <策略id>/              # 如 dividend、grid、dca…
└── holdings/                  # 持仓总账（档案态，借鉴 apps/）
    └── _templates/
        └── holding.md         # 持仓卡：标的/成本/仓位/止损线/决策书引用
```

> 设计取舍：决策书直接放 `decisions/<标的id>/`，而不拆 specs/plans 两层，是因为个人投资里"决策书"天然既是需求又是档案；拆两层反而割裂。交易执行用 plans/ 下的任务卡承接。

### 4.2 决策书状态机（核心：强制复盘闭环）

```
idea（想法，一句话）
  ↓ 填写决策书初稿
research（调研中：基本面/技术面/ETF 持仓查证）
  ↓ 完成投资假设 + 买卖计划
review（评审中：自我挑战 or AI 挑战，意见记入 review.md）
  ↓ 评审通过（用户拍板）
accepted（已批准：此时才允许真实交易）
  ↓ 执行交易
executing（执行中：按交易计划分批）
  ↓ 建仓完成
holding（持有中：定期任务卡跟踪，逻辑变化/触发止损止盈）
  ↓ 清仓
closed（已完结：**必须附复盘报告**，否则不能档案化）
  ↓ 复盘完成
archived（归档：经验沉淀进 RULES.md / 策略包）
```

**状态机硬规则（护栏脚本强制）：**
1. `idea → accepted` 必须经过 `review` 且有评审记录（不能跳过，防冲动直接开买）
2. `review → accepted` 需要用户拍板（交易是动真金白银，必须人确认，AI 不代拍板）
3. **accepted 前不允许出现真实交易记录**（脚本校验 trades/ 下无成交或仅计划）
4. `holding → closed` 必须附复盘报告；**closed 的决策书必须做"假设兑现对照"**（对应 novel 伏笔回收校验）
5. `closed → archived` 前，复盘结论中的经验教训必须更新 RULES.md 或策略包（经验真正落袋）

### 4.3 RULES.md 投资纪律基准（模板要点）

```
## 一、通用纪律（硬约束）
- 单标的仓位上限：XX%（如 ≤ 20%）
- 总仓位规则：权益类 ≤ XX%，ETF 定投 XX%
- 止损纪律：个股 -XX% 强制评估；达到止损线必须执行或写例外理由
- 禁止项：不杠杆、不融资、不追涨停、不做 T+0、不碰 ST/退市风险股

## 二、决策规定
- 任何买入前必须有 accepted 决策书；无决策书不交易
- 投资假设必须可证伪（写清楚"什么情况证明我看错了"）
- 卖出理由必须写（逻辑破坏/达到目标/风险事件，三选一）

## 三、持仓规定
- 每周检查持仓卡的逻辑是否仍成立
- 计划外加减仓必须新开决策书走 review

## 四、复盘规定
- 每笔 close 必须复盘，重点：假设兑现对照 + 纪律遵守情况 + 情绪反思
- 复盘发现的规则漏洞 → 追加到本 RULES.md（沉淀机制，同 zy）
```

> ⚠️ **规则定义权在用户**：上面只是待填范例，用户按自己的风险偏好改写；AI 只执行与兜底。

### 4.4 核心文档模板要点

**decision.md（决策书 / 投资 ADR）**
```markdown
# 决策书：<标的>（<标的id>）
- 状态：idea | research | review | accepted | executing | holding | closed | archived
- 标的类型：个股 / ETF        上次更新：<date>

## 一、投资假设（★核心，必须可证伪）
- 逻辑：为什么买（一句话）
- 关键假设：如"白酒需求复苏，营收增速 ≥ X%"（可验证指标）
- 证伪条件：什么情况证明我看错了（如"连续两季营收负增长"）

## 二、deliverables（本次交易的交付）
- [ ] 买入计划：价位区间 / 仓位占比 / 分批方式
- [ ] 卖出计划：止损线 / 止盈目标 / 退出触发条件
- [ ] 持有期预期：预计持有时长 / 预期收益区间

## 三、out-of-scope（不做什么）
- ❌ 不做：T+0 / 追涨 / 计划外加仓
- ❌ 不因：单日波动 >X% 恐慌割肉

## 四、决策依据（背景/选项/理由，ADR 结构）
- 背景：为什么现在看这个标的
- 选项：买入 / 观望 / 放弃，为什么选了这个
- 风险点 & 最大亏损预期

## 五、validation（验收依据 → 引用 RULES.md）
- [ ] 仓位 ≤ RULES 上限
- [ ] 止损线已设定且符合纪律
- [ ] 假设可证伪（有可验证指标）

## 六、复盘（closed 后填写，对照假设）
- 假设兑现：兑现 / 未兑现 / 部分兑现
- 纪律遵守：完整 / 有偏差（说明）
- 经验教训 → 沉淀到 RULES.md / 策略包
```

**review.md（决策评审 + 复盘表）**
```markdown
## 事前评审（review 阶段）
| 日期 | 评审人 | 挑战点 | 结论 |
|---|---|---|---|
| 2026-10-16 | 自己/AI | 假设是否可证伪？仓位是否超限？ | 通过/打回 |

## 事后复盘（closed 阶段）
- 结果：盈亏 / 持有期
- 假设兑现对照表：| 原假设 | 实际 | 兑现? |
- 纪律检查：止损是否执行？有无计划外操作？
- 情绪反思：决策时是理性还是 FOMO？
- 经验：沉淀条目 → RULES.md 第 X 条 / 策略包
```

**task.trade.md（交易执行卡）**
```markdown
- 关联决策书：<标的id>
- 状态：READY → IN_PROGRESS → DONE
- 操作：买入/卖出/加仓/减仓
- 计划：金额 / 价位 / 数量（必须 ≤ 决策书计划）
验收清单（全勾才能 DONE）：
- [ ] 对应决策书状态 = accepted（未 accepted 不得执行）
- [ ] 操作符合决策书计划（仓位不超限）
- [ ] 成交记录已登记（价格/数量/时间/手续费）
- [ ] 持仓卡已同步更新
```

**strategy.md（策略包，借鉴 worldviews 世界观包）**
```markdown
- 策略 id / 名称 / 版本
## 一、适用条件（什么行情/什么标的使用）
## 二、核心规则（必须遵守的纪律，量化到数）
## 三、deliverables / out-of-scope
## 四、validation（可复用性验收：能不能支撑 ≥2 笔独立决策）
> accepted 后才能被决策书引用（同 novel 世界观包被作品引用）
```

### 4.5 护栏脚本 guard_invest.py 校验逻辑设计

> 完全复用 zy/novel 的脚本模式（Python + Markdown 解析 + 状态机元数据），新增投资专属校验：

1. **状态机强制**：idea→accepted 必须有 review 记录；不能跳 review / 不能从 accepted 回退 idea
2. **决策书完整性**：缺「投资假设」/「证伪条件」/「止损线」→ 拦截（防凭感觉开买）
3. **模糊词检测**（复用 zy）："差不多/再看看/感觉会涨/可能吧" 这类不可证伪表述 → 拦截，要求量化
4. **accepted 前无成交**：trades/ 下出现真实成交但决策书未 accepted → 违规报警（先斩后奏也叫停）
5. **持仓漂移检测**：持仓卡仓位 > RULES 上限 / 止损线被删除 → 报警（对应 novel "人设漂移"）
6. **复盘闭环**：决策书 closed 但 review.md 无复盘记录 → 拦截（对应 novel "伏笔未回收"）
7. **策略包引用校验**：决策书引用的策略包必须 accepted（对应 novel 世界观包引用校验）
8. **DONE 前验收全勾 / BLOCKED 登记原因**（复用 zy）

---

## 五、落地路径建议（分三个阶段，避免一步到位）

### 阶段一：最小可运行（先治"决策无记录"）
1. 建目录 + RULES.md + decision.md/review.md 模板
2. 下一笔交易前，手动写一份决策书（哪怕 10 分钟）
3. 观察 2-3 笔，把模板调到顺手（**先手跑通流程，再自动化**——SDD.md 笔记里的方法论："先找样例手敲，确定格式再交给 AI"）

### 阶段二：护栏脚本化（治"复盘闭环"）
4. 写 guard_invest.py：状态机 + 决策书完整性 + 复盘闭环校验
5. 决策书一律由 AI 按模板起草，用户 review 拍板
6. 每笔 close 强制复盘，脚本把关

### 阶段三：资产化（治"经验不沉淀"）
7. 沉淀策略包（红利/网格/定投…）独立状态机，被决策书引用
8. 标的研报库/公司卡片（类似 novel 世界观包，一标的一卡片，跨决策复用）
9. 可选：接行情/持仓数据自动化（需要时再议，非必须）

## 六、开放式问题（需要你拍板/讨论的点）

| # | 问题 | 我的建议 |
|---|---|---|
| 1 | 决策颗粒度：一个标的开一张决策书（长期持有期）vs 一笔操作开一张（trading 型）？ | 取决于你的风格：偏价值/ETF 用"标的一张"，偏短线用"操作一张"。可像 zy 场景化模板一样做两种卡型 |
| 2 | AI 的角色边界：AI 只负责记录/起草模板/校验纪律，还是也参与分析建议？ | 建议**分析可参与，决策不代拍**（类似 spec review 用户拍板）。毕竟账户是你的 |
| 3 | 是否与现有 zy-sdd-spec 融合：invest-sdd 做成 zy 的领域包（像 novel-sdd）vs 完全独立技能？ | 建议仿 novel-sdd 做独立领域包，但复用 zy 的 guard 脚本骨架 |
| 4 | 复盘频率：每笔 close 一次 vs 月度统一复盘？ | 建议两者都要：close 必复盘（闭环校验），月度组合复盘（可做可不做，先不做） |
| 5 | 要不要接真实行情/持仓自动同步？ | 第一版强烈建议纯手动 + 模板记录，跑顺再自动化 |
| 6 | 策略包/标的库一开始就建，还是跑几笔后再沉淀？ | 同 novel 世界观包的教训：先跑通再资产化，不要为建而建 |

## 七、一句话总结

> **投资的 SDD = 把每一笔交易当成一次"可验收的开发任务"：写决策书（规范先行）→ 评审拍板（状态机把关）→ 按计划执行（任务卡验收）→ 复盘对照假设（闭环回收）→ 经验沉淀进纪律库（可复利资产）。**
> 三个技能教会我们的核心：SDD 的价值不在于文档，而在于**把"凭感觉"变成"可追溯"，把"忘了"变成"强制"**——这正好是投资人最缺的两样东西。
