# novel-sdd · 小说 / 短文 / 短故事的规范驱动体系

> **这是模板和规范，不是一个待写的项目。** 目录里除了样例，没有任何你的正文。
>
> 它解决一个具体问题：**故事一长，前后设定、伏笔、用词就开始互相打架。**

---

## 为什么会有这个东西

长上下文写作的矛盾，从来不是"AI 记性不好"。真原因是：**一致性只活在你的记忆和上一段对话里。**

记忆会衰减，对话会截断。所以：

- 第三章把"灵力"写成了"灵能"，到第十二章读者已经分不清这是什么
- 第一章埋的东西，写到第八章完全忘了，结局只能硬凑
- 同一个角色，前一篇里三十岁，后一篇里二十五岁，因为没人记得

**这套东西的做法是：把一致性从脑子里搬出来，变成磁盘上能被机器校验的结构。**

不是要求你记住，是让你忘不掉。

## 三层结构

```
worlds/          ★ 世界观包（可复利资产，独立状态机）
  W-001/
    world.md           总设定：世界规则 / 基调 / 术语表
    world_review.md    世界观评审（定稿前必须过）
    characters/        人物卡，一人一张
    老周.md

stories/         故事层（= spec，每篇一份）
  ST-001/
    story.md           故事设定书：一句话故事 / 不写什么 / 验收标准
    review.md          评审 + 复盘
    threads.md         ★ 伏笔追踪表：埋 → 收
    outline.md         章纲（中篇/长篇才需要）

chapters/        章节层（= task，一章一卡）
  ST-001/
    ch-01-井边.md      章节卡 + 正文
```

**关键：故事层不重复定义世界规则，只写「这一篇要干什么」。**
一个世界观可以挂 N 篇故事 —— 这正是你要的复用。

## 三个机制，逐个说

### 一、世界观子包：写新故事不再重新造世界

```
draft → review → accepted ──冻结──→ （要改？走 changes/ 变更单）
```

- 世界观 **accepted 之后就冻结**。想改，必须在 `world.md` 第七节留一行变更记录，
  并且在 `changes/` 建变更单，写清「影响哪些已写故事」。
- **偷偷改设定会被拦**：版本号改成 1.1 但变更记录是空的，脚本直接报错。
- 开新故事时，`story.md` 里只写 `world: W-001`，设定一个字都不用抄。
- 想在故事里临时用个新设定，记在 `story.md` 第六节「本篇新增的设定」，
  标注「仅本篇有效」或「已提升到世界观」。**先记着，别急着进世界观。**

这就是你要求的：**除非要开新世界，否则不动世界观。**

### 二、术语表：同一概念只能有一种写法 ★

这是整套体系里最实用的一个设计。世界观里有一张表：

| 术语 | 唯一写法 | 禁止写法（出现即拦） | 释义 |
|---|---|---|---|
| 井 | 井 | 水井、神井、灵井 | 街心那口古井 |
| 铜钱 | 铜钱 | 铜子、古钱、铜板 | 出生时分到的旧钱 |

**脚本会扫每一章正文，出现「禁止写法」就报错，并告诉你该写什么。**

样例里 ST-001 的第二稿写过一次「水井」，就是被这个拦下来的。
这个功能专门治「同一东西三种叫法」——那是世界崩塌最快的方式，而且你自己很难发现。

### 三、伏笔追踪：埋了必须收

`stories/<id>/threads.md` 一张表：

| id | 伏笔内容 | 埋设章 | 计划回收章 | 状态 |
|---|---|---|---|---|
| F-001 | 井水上飘着一枚不是陈默的铜钱 | ch-01 | ch-03 | paid |

同时，章节卡的 frontmatter 要标注：

```yaml
plants: F-002        # 本章埋下
pays: F-001,F-003    # 本章回收
```

**两边交叉校验：**

- 章节说 `pays: F-001`，但伏笔表里没有 F-001 → 报错
- 伏笔表说 paid，但没有任何章节标注收它 → 警告
- 故事完结了还有 `open` 的伏笔 → **拦截**（挖坑不填，读者会记仇）
- 标了 `dropped` 但没写为什么放弃 → 警告

**这样「写忘了」就从记性问题变成了机器问题。**

## 30 秒上手

```bash
# 1. 看规则，把数值改成你的习惯（单章字数、哪些篇幅要章纲）
#    改 RULES.md 里 RULES-BEGIN / RULES-END 之间

# 2. 建世界观
python bin/init_novel.py world W-001 青石镇

# 3. 填世界规则 + 术语表（★ 术语表的「禁止写法」列认真填，这是最有用的部分）

# 4. 建人物
python bin/init_novel.py character W-001 陈默

# 5. 写第一篇
python bin/init_novel.py story ST-001 井底的铜钱 --world W-001 --form short
python bin/init_novel.py chapter ST-001 井边

# 6. 随时校验
python bin/guard_novel.py
```

想看「写到什么程度才算到位」：

```bash
python bin/init_novel.py demo
```

生成 `examples/`：一个世界观（青石镇）下挂两篇故事 —— ST-001 已完结（伏笔全闭环），
ST-002 在写（有意留白）。**两篇共享同一个世界观，这是重点。**

## 状态机

```
世界观：draft → review → accepted ─(要改)→ revising → accepted
                            ↑
                       accepted 后冻结

故事：  idea → outlining → drafting → revising → done → archived
                                 ↑
                          动笔前 review 必须 pass

章节：  TODO → DRAFT → REVISED → DONE
```

## 护栏拦什么（16 类）

| 组 | 校验项 |
|---|---|
| **W 世界观** | 定稿必须有评审 / 世界规则不许空 / 术语表不许空 / 改了版本必须有变更记录 |
| **S 故事** | 评审通过才能动笔 / 一句话故事不许空 / 不写什么不许空 / 验收≥3条且不许写"好看" / 中篇长篇必须有章纲 / 引用的世界观必须已定稿 |
| **C 章节** | DONE 前验收全勾 / 字数在区间内 / 章节 id 不重复 |
| **F 伏笔** | ⭐ 埋了没回收就完结 = 拦 / 章节引用不存在的伏笔 = 拦 / paid 但没有章节标注 = 警告 / dropped 没写原因 = 警告 |
| **T 一致性** | ⭐ 正文出现术语的禁止写法 = 拦 / 已故人物在后文出场 = 警告 / 人物引用必须在世界观里有卡 = 拦 |

### 退出码

| 码 | 含义 |
|---|---|
| 0 | 通过（可能有警告） |
| 1 | 有错误，或 `--strict` 下算上警告 |
| 2 | 环境问题（世界观不存在、必须指定 world） |

```bash
python bin/guard_novel.py              # 全量
python bin/guard_novel.py ST-001       # 单篇
python bin/guard_novel.py --strict     # 警告也算失败（完结前建议这么跑）
```

## 日常流程

### 写一篇新故事（复用已有世界观）

```bash
python bin/init_novel.py story ST-003 新故事 --world W-001 --form short
```

只需要：
1. 填「一句话故事」——谁、想要什么、什么挡着、付出什么代价
2. 填「不写什么」——**短篇写崩基本都是想塞太多**
3. 第三节「人物」只填人物 id，详细设定去世界观看
4. 状态推到 `drafting` 前，review.md 的 verdict 改 `pass`

### 写到一半发现要用新设定

记在 `story.md` 第六节：

| id | 新增设定 | 去留 |
|---|---|---|
| N-003 | 井水照不出重来过的人 | 待定 |

**不要直接改世界观。** 等这篇写完，看它值不值得提升。

### 想把经验提升到世界观

1. 改 `worlds/W-001/world.md`，版本号 +0.1
2. 第七节变更记录写一行：改了什么、为什么、影响哪些故事
3. 在 `changes/` 建变更单
4. 跑一次全量校验，看看被影响的故事有没有报错

### 完结前

```bash
python bin/guard_novel.py --strict
```

`--strict` 会把警告也算失败。完结前必须这么跑一次 —— 这是最后的清算。

## 与另外两套的关系

`../invest-sdd/` 和 `../dev-sdd/` 是同一套内核的另外两个领域包：

| | 小说版 | 开发版 | 投资版 |
|---|---|---|---|
| 真源 | `stories/` | `specs/` | `decisions/` |
| 执行 | `chapters/` | `tasks/` | `plans/` |
| 可复利资产 | `worlds/` | `modules/` + `adr/` | `strategies/` |
| 领域校验 | **术语一致 / 伏笔闭环** | 验收可测 / 依赖成环 | 假设可证伪 / 仓位漂移 |

**小说版独有的是「术语禁止写法扫描」** —— 因为只有写作场景会出现"同一个东西三种叫法"。

## 已知陷阱（改代码前必读）

前两条在投资版和开发版上各踩过，这套是第三次实现，已经固定写法：

1. **`\s` 含换行** —— Markdown 单行解析一律用 `[^\n]*` / `[ \t\u3000]*`，绝不用 `.*` / `\s*`。
   否则空字段会读到下一行、多个 checkbox 会合并成一个。
2. **标题层级** —— `section()` 要支持 2~6 级标题，且按级别判断段落边界。
   只匹配 `^##\s` 会让 `### xxx` 被并进上一段。
3. **模板说明与用户内容必须可区分** —— 模板里的格式提示统一以 `> 说明：` 开头。
   否则「一句话故事」这种字段，无法判断用户到底写了没有。
4. **字数统计剔除标点** —— 中文引号要写成 `\u201c` 转义，直接写会截断 raw string
   并让后面的 `\-` 变成非法转义（编译时会有 SyntaxWarning）。

## 维护

```bash
python .dev/selfcheck.py     # 25 个用例，一半是「故意写错 → 必须被拦」
```

改 `bin/guard_novel.py` 之后必须跑。错误码分段：`W`（世界观）/ `S`（故事）/ `C`（章节）/ `F`（伏笔）/ `T`（一致性）/ `P`（人物）。
