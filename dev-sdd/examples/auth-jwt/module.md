# 方案包：JWT 认证方案（auth-jwt）

> 这是「可复利资产」层：把一次做完的方案抽成包，下次直接引用，不用重新想一遍。

## 一、适用场景

- **什么时候用**：单体或少量实例的后端，需要无状态认证，且能接受「不能即时吊销」
- **什么时候不用**：★ 需要即时踢下线 / 单点登录 / 高安全等级场景 —— 这些情况用服务端 Session

## 二、核心做法

1. token 有效期 **2 小时**，不做 refresh token（本阶段不需要长登录）
2. 密码用 bcrypt（cost=12）存储，**任何日志都不打印密码字段**
3. 登录失败提示语**统一为「账号或密码错误」**，不区分账号是否存在（防账号枚举）
4. 失败计数用**数据库原子自增**，不要先读后写（并发会丢计数）
5. 校验中间件挂在受保护路由组上，白名单走配置，不写死在代码里

## 三、关键实现位置

| 内容 | 位置 |
|---|---|
| 签发 / 校验 | `services/auth.py` |
| 中间件 | `middleware/auth.py` |
| 配置项 | `config/auth.yaml`（`auth.mode` 可切回 session） |

## 四、踩过的坑

> 这些是别人拿过去用能直接省下的时间。

- **先读后写改计数会丢数**：并发下 10 次错误只记到 3 次。必须用 `SET x = x + 1` 原子操作。
- **测试环境时钟偏差**：服务器和测试机差 8 分钟，token 过期用例时好时坏。测试里注入固定时钟。
- **前端存 localStorage**：退出登录只是删了本地 token，服务端签发的那个在过期前依然有效。要让用户知道这个边界，别承诺"退出即失效"。
