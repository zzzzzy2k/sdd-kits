# invest-sdd · 投资决策的规范驱动体系

> 把每一笔交易当成一次**可验收的开发任务**：
> 写决策书（规范先行）→ 评审拍板（状态机把关）→ 按计划执行（任务卡验收）→
> 复盘对照假设（闭环回收）→ 经验沉淀进纪律库（可复利资产）。
>
> 面向个人投资者 · A 股 + ETF · 决策记录与复盘闭环。
> 零依赖（纯 Python 标准库）、零技术栈绑定、全部数据以 Markdown 存本地。

---

## 一句话

**投资的 SDD 不解决「你判断得对不对」，它解决「你判断过没有、怎么判断的、后来兑现了没有」。**

脚本校验不了「这个判断好不好」，但能保证「有记录、有对照、有闭环」——那恰好是个人投资者最缺的两样东西：
把「凭感觉」变成「可追溯」，把「忘了」变成「强制」。

## 状态机（核心：强制复盘闭环）

```
idea（想法，一句话）
  ↓ 填写决策书初稿
research（调研中：基本面 / 技术面 / ETF 持仓查证）
  ↓ 完成投资假设 + 买卖计划
review（评审中：自我挑战或 AI 挑战，意见记入 review.md）
  ↓ 评审通过（★ 用户拍板，AI 不代拍）
accepted（已批准：★ 此时才允许真实交易）
  ↓ 执行交易
executing（执行中：按交易计划分批）
  ↓ 建仓完成
holding（持有中：任务卡定期跟踪，逻辑变化 / 触发止损止盈）
  ↓ 清仓
closed（已完结：★ 必须附复盘报告，否则不能档案化）
  ↓ 复盘完成
archived（归档：经验沉淀进 RULES.md / 策略包）
```

**硬规则（`guard_invest.py` 强制，绕不过去）：**

1. `idea → accepted` 必须经过 `review` 且有评审记录 —— 防冲动直接开买
2. `review → accepted` 需要人拍板（交易动真金白银，AI 只起草不代签）
3. **accepted 之前不允许出现真实成交** —— 先斩后奏也叫停
4. `closed` 必须做「假设兑现对照」—— 写了假设不对账 = 缺陷
5. `archived` 前经验必须落进 RULES.md 或策略包 —— 否则等于白复盘

## 目录结构

```
invest-sdd/
├── README.md                    ← 你在看的这份
├── RULES.md                     ★ 投资纪律基准（你改，脚本读）
├── bin/
│   ├── init_invest.py           脚手架（建决策书 / 策略包 / 任务卡）
│   ├── guard_invest.py          ★ 护栏脚本（8 类校验）
│   └── demo.py                  生成完整流程样例
├── decisions/                   ★ 决策层（唯一真源）
│   ├── _templates/
│   │   ├── decision.md          决策书模板（= 投资 ADR）
│   │   └── review.md            评审 + 复盘模板
│   └── <标的id>/                如 600519、510880
│       ├── decision.md          决策书（带状态机）
│       └── review.md            评审 / 复盘记录
├── plans/                       执行层
│   ├── _templates/
│   │   ├── plan.md              交易计划（分批建仓表 / 退出条件）
│   │   ├── task.trade.md        交易执行卡（一笔一卡）
│   │   └── task.monitor.md      持仓跟踪卡（定期检查）
│   └── <标的id>/
│       ├── plan.md
│       ├── task-01-buy.md
│       └── task-02-monitor.md
├── strategies/                  ★ 策略包（可复利资产）
│   ├── _templates/
│   │   ├── strategy.md          适用条件 / 核心规则 / 不适用场景
│   │   └── strategy_review.md
│   └── <策略id>/                如 dividend、grid、dca
├── holdings/                    持仓总账（档案态）
│   └── <标的id>.md              持仓卡：成本 / 仓位 / 止损线 / 决策书引用
└── examples/                    跑完全程的样例（不被校验）
```

> **为什么决策书直接放 `decisions/<标的id>/` 而不拆 specs/plans 两层**：
> 个人投资里「决策书」天然既是需求又是档案，拆两层反而把一件事割裂成两处维护。
> 交易执行用 `plans/` 下的任务卡承接，边界照样清楚。

## 日常流程

### 买之前

```bash
python bin/init_invest.py decision 600519 贵州茅台     # 建决策书
# 填「一、投资假设」：逻辑 / 关键假设 / 证伪条件 / 验证方式
# 状态 idea → research，写买卖计划
# 状态 → review，填 review.md 的事前评审，自己挑战自己一遍
# 评审通过 → status 改 accepted，verdict 改 pass
python bin/guard_invest.py 600519                      # 必须 0 错误
```

> 卡在 accepted 之前，脚本会一直报错——这就是它的价值。

### 买的时候

```bash
python bin/init_invest.py plan 600519                  # 交易计划
python bin/init_invest.py task 600519 buy              # 执行卡
# 成交后：filled 改 true，补 fill_price / fill_qty / fill_date
# 勾完四行验收清单，status 改 DONE
python bin/init_invest.py holding 600519               # 同步持仓卡
```

### 拿着的时候

```bash
python bin/init_invest.py monitor 600519               # 每周一张跟踪卡
```

### 卖完以后

```bash
# 状态 → closed，review.md 的 verdict 保持 pass，hypothesis_result 填 fulfilled/failed/partial
# 「事后复盘」写假设兑现对照表 + 纪律检查 + 情绪反思
python bin/guard_invest.py 600519                      # 复盘没写就过不了

# 状态 → archived，同时把经验写进 RULES.md 第五章
```

## 护栏拦什么（8 类校验）

| # | 校验项 | 触发条件 | 对应痛点 |
|---|---|---|---|
| 1 | **状态机强制** | accepted 后缺 review.md / verdict 不是 pass / 无评审日期 | 决策无记录 |
| 2 | **决策书完整性** | accepted 后「逻辑 / 关键假设 / 证伪条件 / 止损线」任一为空 | 凭感觉开买 |
| 3 | **模糊词检测** | 「感觉会涨 / 差不多 / 看着办」一律拦；「可能 / 大概 / 待定」accepted 后升级为错误 | 不可验收 |
| 4 | **accepted 前无成交** | `filled: true` 但决策书状态还没 accepted | 先斩后奏 |
| 5 | **持仓漂移** | 仓位超 RULES 上限 / 止损线留空 / 关联决策书已 closed 但持仓卡还在 | 持仓失控 |
| 6 | **复盘闭环** | closed 但 `hypothesis_result` 未填，或事后复盘章节过简 | 假设不验证 |
| 7 | **策略包引用** | 引用的策略包不是 accepted（或被删） | 经验不沉淀 |
| 8 | **任务卡验收** | DONE 但验收清单还有未勾项；BLOCKED 但没写原因 | 执行放水 |

额外还查：状态回退（警告，允许但你得知道）、模板占位符没替换、止损线比纪律更松（警告）。

### 退出码

| 码 | 含义 |
|---|---|
| 0 | 通过（可能有警告） |
| 1 | 有错误，或 `--strict` 下算上警告 |
| 2 | 环境 / 解析问题（模板缺失、标的不存在） |

```bash
python bin/guard_invest.py              # 全量
python bin/guard_invest.py 600519       # 单标的
python bin/guard_invest.py --strict     # 警告也算失败（想严格要求自己时用）
python bin/guard_invest.py --quiet      # 只输出问题
```

## 三个关键设计决策

### 1. 决策书就是投资 ADR

「背景 → 选项 → 结果 → 理由」一页纸。这来自 benben-spec 的架构决策记录机制。
**有价值的不是结论，是你当初比较过哪几个选项、为什么排除了它们。**
半年后回看时，"当时还考虑过观望"比"我看好它"信息量大得多。

### 2. 证伪条件比目标价重要

样例里那句反思是真的：4 月连跌时挡住冲动的不是目标价，是「证伪条件没触发」。
**写清楚什么情况算我错了，比写清楚能涨多少有用。**
所以它是护栏的第 2 条必填项，空了直接拦。

### 3. 策略包是「可复利资产」

借 novel-sdd 的世界观包设计：策略独立于具体标的走自己的状态机（draft → review → accepted），
**只有 accepted 才能被决策书引用**。这样"红利策略"这套规则只写一次，后面 N 笔决策直接引用——
经验从「每次重新想」变成「引用一份已经验收过的纪律」。

## 维护

### 改模板

模板即真源，改 `_templates/` 下的文件，之后新建的决策书就跟着变（已有文件不动）。

### 改规则

只改 `RULES.md` 里 `RULES-BEGIN / RULES-END` 之间的键值对。**格式别动**，脚本靠它解析。
加了未知的键会警告（防拼错）。

### 改护栏逻辑

`bin/guard_invest.py` 里每条规则对应一个 `check_*` 函数，错误码 `D0xx / P0xx / H0xx / S0xx` 分段管理。

**改完必须跑回归测试**：

```bash
python .dev/selfcheck.py
```

18 个用例，其中一半是「故意违规 → 必须被拦」的反向用例。
护栏脚本最危险的失效方式是**静默放行**——不报错但规则没生效，比报错可怕得多。
这个坑本神人已经踩过一次（见下方「已知陷阱」）。

### 已知陷阱（改代码前必读）

1. **正则里的 `\s*` 会吃掉换行** —— 字段值为空时会读到下一行内容，导致「投资假设为空」漏报。
   解析 Markdown 单行字段时，冒号后只能用 `[ \t\u3000]*`，不能用 `\s*`。
2. **止损线匹配不能太松** —— `止损线[^\n]*\d` 会把「止盈 +20%」的 20 当成止损线，
   让空止损的决策书蒙混过关。必须用 `STOP_RE`（紧邻 + 不跨分号）。
3. **状态快照存在 `.state/guard-state.json`** —— 用于检测状态回退。删了不影响校验，只是丢失回退检测。
